1. Project & subsystem overview

Cycle Care is an offline-capable menstrual health app for teenage girls in rural Sri Lankan schools, many using a shared family phone with poor connectivity. Five principles apply to every screen: offline-first, privacy by design, low cognitive load, bilingual, calm non-stigmatising visuals.

#SubsystemOwner

3Private Education (PIN entry, Education Hub, articles, Offline Library, Myth Buster)A M S P Aththanayake
4Healthcare Access (pharmacy directory)K G L S Senadeera

Requirements covered: REQ-3.1 (secure, discreet entry on shared phones), REQ-3.2 (vital health information available offline), plus FR6 (offline), FR8 (Sinhala + English) and FR9 (PIN protection).

4. Navigation & app flow

MainScreen hosts a bottom navigation bar with three tabs: Dashboard (Member 2), Calendar (Member 2) and Learn (Member 3, the Education Hub).

PrivacyLockScreen --(correct PIN)--> MainScreen
 MainScreen → Learn tab → EducationHubScreen
   ├─ Our Body / Food & Diet → CategoryScreen → ArticleScreen
   ├─ Daily Tip "Read More"   → ArticleScreen
   ├─ Search results          → ArticleScreen
   ├─ Saved Library           → OfflineLibraryScreen → ArticleScreen
   └─ Myth Buster             → MythBusterScreen
HIDE (any screen) → MainScreen (stack cleared, no animation)
Current setting: at your request, main.dart opens MainScreen directly (the PIN screen will be wired in later). If PrivacyLockScreen is ever reached with no PIN set, it unlocks the session and forwards to MainScreen; the PIN-setup stub has a “Continue to App” button. To test the lock, restore home: PrivacyLockScreen() and run with --dart-define=DEMO_PIN=1234.

AppRoutes centralises navigation: push, replace, and resetTo (clears the whole stack with a zero-duration PageRouteBuilder; used by HIDE).

5. Privacy features

PIN lock (REQ-3.1)

  • PIN hashed with PBKDF2-SHA-256, random 16-byte salt (Random.secure()), 10,000 iterations; stored as {salt, hash} – never plain text.
  • Unlock state lives in memory only; every cold start requires the PIN.
  • 5 failures → 30-second lockout with visible countdown; stored in Hive so an app restart does not reset it.
  • Android Back is blocked on the lock screen (PopScope(canPop:false)).
  • A 4-digit PIN deters family members; it is not strong security – documented honestly in code comments.
  • Dev seed: --dart-define=DEMO_PIN=1234 creates a PIN on first run.

Panic HIDE button

  • High-contrast pill with icon + label, top-right of the article (and other screens). One tap, no confirmation.
  • Dismisses toasts, locks the session, and calls AppRoutes.resetTo(MainScreen) – the article cannot be reached with Back.
  • Target < 2 s; measured in practice in milliseconds (no transition animation).

Other privacy measures

  • No analytics, no third-party requests, no PII in logs.
  • Fonts, content and images are bundled; GoogleFonts.config.allowRuntimeFetching = false.

6. Hive local storage explained

Hive is a fast, offline NoSQL key-value store. On mobile/desktop it writes .hive files to the app sandbox; on web it uses IndexedDB.

BoxType IDOwnerContents
cycle_entries0 (CycleEntry)Member 2Daily flow/symptoms/mood keyed by date
saved_articles1 (SavedArticle)Member 3articleId, savedAt; key = articleId
settings– (dynamic)Sharedkeys: pin, pin_lock, lang, profile, quiz

Initialisation in main(): LocalStorageService.init() (Hive.initFlutter() + CycleEntry adapter), SavedArticlesStore.init() (SavedArticle adapter + box), MockPinService.init() (settings box).

Access pattern: widgets never call raw Hive.box; they use SavedArticlesStore (save, remove, toggle, isSaved, all, count). SavedArticlesStore.listenable (box.listenable()) drives a ValueListenableBuilder, so the hub’s “{n} Guides Offline” count and the library list update instantly after a save or removal.

7. Content, bilingual support & offline behaviour

  • Content types: Article, MythQuestion, DailyTip, blocks (HeadingBlock, ParagraphBlock, ListBlock, TipBlock), each text field a Localized<T> with en and si.
  • Seed articles (7): iron-rich-foods, water-hydration, foods-to-limit, understanding-your-cycle, what-is-a-period, hygiene-basics, hygiene-at-school. IDs are stable for deep-linking.
  • Myth Buster: 5 questions, shuffled each run; daily tips (5–7) chosen deterministically from the date.
  • UI strings: t('key', lang: lang) from l10n/strings.dart; tests ensure English and Sinhala key sets match.
  • Offline: zero network calls. Content from BundledRepository, fonts from assets/google_fonts/ (Outfit, Noto Sans Sinhala), data in Hive.
  • Sinhala text and health content are marked for native-speaker / health-professional review.

9. Accessibility

  • Semantics/tooltips on icon-only controls (back, HIDE, delete key); toast announced as a live region.
  • Tap targets ≥ 48 dp; keypad keys ≥ 64 dp.
  • Layouts verified at 1.5× text scale without overflow; reduced-motion respected (shake skipped).
  • Long Sinhala strings never clipped (line height ≥ 1.6).

10. User-testing instrumentation

Enabled with --dart-define=TEST_MODE=true. MetricsService records timestamped events in memory only (no PII, no network): lock_shown, pin_key, pin_error, unlocked, nav, article_open, save_offline, toast_shown, hide_tap, hide_done.

TestModeOverlay shows a draggable TEST • n taps badge. Tap it for a dashboard with metrics, Reset Session and Export JSON (copies to clipboard). The Think-Aloud script (5 participants), facilitator text and observation sheet are in docs/user-testing.md.

13. Manual UI test walkthrough

  1. Hub: tap the Learn tab. Check greeting, search, Daily Tip card (pink gradient), 2×2 topics.
  2. Search: type “iron” or “cramp”; results filter instantly; open one.
  3. Category: Food & Diet → chips All Tips / Cramp Relief / Vitamins filter the list.
  4. Article: open Iron-Rich Foods; verify Village Tip. Tap Save → green “✓ Saved Offline” + toast; tap again to un-save.
  5. HIDE: tap HIDE → instant return to MainScreen; Back cannot reopen the article.
  6. Library: Saved Library tile shows the count; open the list, Read Offline, remove, view empty state.
  7. Myth Buster: answer 5 questions, read feedback, check results and personal best, Play again.
  8. Test mode: with TEST_MODE=true, drag the badge, open metrics, export JSON, reset.

A fuller checklist is in docs/manual-testing-guide.md.

14. Integration guide for other members

Member 1 – Onboarding & PIN

  • Replace PinSetupStubScreen; call pinService.set(pin) to store the hash; then navigate onward.
  • Write settings['lang'] ('en'/'si') – Member 3’s screens rebuild automatically.
  • Optional settings['profile'] = {displayName} adds a name to the hub greeting.
  • PinService contract: isSet(), verify(pin), set(pin).

Member 2 – Tracking

  • MainScreen tabs: 0 Dashboard, 1 Calendar, 2 Learn.
  • Deep-link to articles: AppRoutes.push(context, ArticleScreen(articleId: 'water-hydration')) (e.g. cramps → water-hydration, fatigue → iron-rich-foods).
  • Use HideButton and AppRoutes.resetTo for instant exit.

Member 4 – Pharmacy

  • Replace PharmacyStubScreen; articles recommending a health worker can link to it.

Full details: docs/integration.md.
